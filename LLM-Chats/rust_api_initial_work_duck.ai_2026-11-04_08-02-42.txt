## Suggested design

Use one GraphQL endpoint, such as `POST /graphql`, with **queries** for reads and **mutations** for changes or actions. GraphQL can also support `GET` for read-only queries, but using `POST` consistently is simpler for clients. Your 1.A–1.F operations map to GraphQL fields rather than separate REST endpoints.

A practical Rust stack is `axum` + `async-graphql` + `sqlx` + PostgreSQL. `async-graphql` supports Axum integration and lets you set query depth and complexity limits. [1]

### GraphQL API

```graphql
type Query {
  podmanRepoStatus: ServiceStatus!
  buildServerStatus: BuildServerStatus!
  managedApps: [ManagedApp!]!
  buildJob(id: ID!): BuildJob
}

type Mutation {
  changeAppVersion(appId: ID!, version: String!): ManagedApp!
  restartPodmanRepo: ActionResult!
  runBuild: BuildJob!
}

type ServiceStatus {
  state: ServiceState!
  checkedAt: String!
  message: String
}

type BuildServerStatus {
  state: BuildServerState!
  checkedAt: String!
  currentJobId: ID
}

type ManagedApp {
  id: ID!
  name: String!
  endpoint: String
  version: String
}

type BuildJob {
  id: ID!
  state: JobState!
  startedAt: String
  finishedAt: String
  message: String
}

type ActionResult {
  accepted: Boolean!
  message: String!
}

enum ServiceState { ACTIVE DOWN UNKNOWN }
enum BuildServerState { ACTIVE IDLE DOWN UNKNOWN }
enum JobState { QUEUED RUNNING SUCCEEDED FAILED }
```

- `podmanRepoStatus` and `buildServerStatus` should report observed health, not assume a service is down merely because a check timed out. Return `UNKNOWN` and include a message when status cannot be determined.
- `changeAppVersion` should validate the app and version, then update the database transactionally.
- `restartPodmanRepo` and `runBuild` should enqueue controlled jobs and return promptly. Track job status so clients can poll `buildJob(id)`; don’t keep the GraphQL request open while a long build runs.
- Define what “changed apps” means—for example, apps whose recorded version differs from the last successfully built version. Your proposed three tables don’t store that history, so either add build/job history tables or have a separate job system retain it.

### SQL build script

This PostgreSQL schema keeps the requested three tables. It stores one current version per application; `version` is a reserved-looking identifier in some contexts, so the SQL uses `app_version` as the table name.

```sql
BEGIN;

CREATE TABLE application (
    id          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name        TEXT NOT NULL UNIQUE,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT application_name_not_blank CHECK (length(trim(name)) > 0)
);

CREATE TABLE endpoint (
    id          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    app_id      BIGINT NOT NULL REFERENCES application(id) ON DELETE CASCADE,
    url         TEXT NOT NULL,
    CONSTRAINT endpoint_url_not_blank CHECK (length(trim(url)) > 0),
    CONSTRAINT endpoint_app_url_unique UNIQUE (app_id, url)
);

CREATE TABLE app_version (
    id          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    app_id      BIGINT NOT NULL UNIQUE
                REFERENCES application(id) ON DELETE CASCADE,
    version     TEXT NOT NULL,
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT app_version_not_blank CHECK (length(trim(version)) > 0)
);

COMMIT;
```

`UNIQUE (app_id)` makes `app_version` the current version record for each app. If you want version history, remove that constraint and add a timestamp or sequence column, then query the latest record as the current version.

**Operational safeguards:** require authentication and authorization for mutations; allow only configured build/restart actions; validate app IDs and version strings; and record who initiated each action and its outcome. Keep the Podman control interface inaccessible to untrusted clients.

```rust
use async_graphql::{
    Context, EmptySubscription, Object, Schema, SimpleObject,
};
use async_graphql_axum::{GraphQLRequest, GraphQLResponse};
use axum::{routing::post, Router};
use sqlx::{FromRow, PgPool, postgres::PgPoolOptions};
use std::net::SocketAddr;

type ApiSchema = Schema<QueryRoot, MutationRoot, EmptySubscription>;

#[derive(SimpleObject, FromRow)]
struct ManagedApp {
    id: i64,
    name: String,
    endpoint: Option<String>,
    version: Option<String>,
}

#[derive(SimpleObject)]
struct ServiceStatus {
    state: String,
    message: Option<String>,
}

struct QueryRoot;

#[Object]
impl QueryRoot {
    async fn managed_apps(&self, ctx: &Context<'_>) -> async_graphql::Result<Vec<ManagedApp>> {
        let pool = ctx.data::<PgPool>()?;

        let apps = sqlx::query_as::<_, ManagedApp>(
            r#"
            SELECT
                a.id,
                a.name,
                (
                    SELECT e.url
                    FROM endpoint e
                    WHERE e.app_id = a.id
                    ORDER BY e.id
                    LIMIT 1
                ) AS endpoint,
                v.version
            FROM application a
            LEFT JOIN app_version v ON v.app_id = a.id
            ORDER BY a.name
            "#
        )
        .fetch_all(pool)
        .await?;

        Ok(apps)
    }

    // Placeholder until you connect a real health check.
    async fn podman_repo_status(&self) -> ServiceStatus {
        ServiceStatus {
            state: "UNKNOWN".into(),
            message: Some("Health check is not configured".into()),
        }
    }

    // Placeholder until you connect a real build-worker status check.
    async fn build_server_status(&self) -> ServiceStatus {
        ServiceStatus {
            state: "UNKNOWN".into(),
            message: Some("Build-server status check is not configured".into()),
        }
    }
}

struct MutationRoot;

#[Object]
impl MutationRoot {
    async fn change_app_version(
        &self,
        ctx: &Context<'_>,
        app_id: i64,
        version: String,
    ) -> async_graphql::Result<ManagedApp> {
        let pool = ctx.data::<PgPool>()?;

        let version = version.trim();
        if version.is_empty() {
            return Err("Version must not be empty".into());
        }

        let app = sqlx::query_as::<_, ManagedApp>(
            r#"
            WITH updated AS (
                INSERT INTO app_version (app_id, version)
                VALUES ($1, $2)
                ON CONFLICT (app_id)
                DO UPDATE SET version = EXCLUDED.version,
                              updated_at = now()
            )
            SELECT
                a.id,
                a.name,
                (
                    SELECT e.url
                    FROM endpoint e
                    WHERE e.app_id = a.id
                    ORDER BY e.id
                    LIMIT 1
                ) AS endpoint,
                v.version
            FROM application a
            LEFT JOIN app_version v ON v.app_id = a.id
            WHERE a.id = $1
            "#
        )
        .bind(app_id)
        .bind(version)
        .fetch_optional(pool)
        .await?
        .ok_or_else(|| async_graphql::Error::new("Application not found"))?;

        Ok(app)
    }

    // These return errors rather than pretending an action happened.
    async fn restart_podman_repo(&self) -> async_graphql::Result<String> {
        Err("Restart action is not configured".into())
    }

    async fn run_build(&self) -> async_graphql::Result<String> {
        Err("Build action is not configured".into())
    }
}

async fn graphql_handler(
    axum::extract::State(schema): axum::extract::State<ApiSchema>,
    req: GraphQLRequest,
) -> GraphQLResponse {
    schema.execute(req.into_inner()).await.into()
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    dotenvy::dotenv().ok();

    let database_url =
        std::env::var("DATABASE_URL").expect("DATABASE_URL must be set");

    let pool = PgPoolOptions::new()
        .max_connections(10)
        .connect(&database_url)
        .await?;

    let schema = Schema::build(QueryRoot, MutationRoot, EmptySubscription)
        .data(pool)
        .finish();

    let app = Router::new()
        .route("/graphql", post(graphql_handler))
        .with_state(schema);

    let addr: SocketAddr = std::env::var("LISTEN_ADDR")
        .unwrap_or_else(|_| "127.0.0.1:8000".into())
        .parse()?;

    let listener = tokio::net::TcpListener::bind(addr).await?;
    println!("GraphQL API listening at http://{addr}/graphql");

    axum::serve(listener, app).await?;
    Ok(())
}
```

That error means there’s no PostgreSQL server listening at `/run/postgresql/.s.PGSQL.5432`. PostgreSQL may be stopped, uninitialized, or using a different socket directory.

On Void, first check whether a PostgreSQL service is running:

```bash
sudo sv status postgresql
```

If it says `down` or the service doesn’t exist, Void may need PostgreSQL initialized and a runit service configured; installing the package alone may not start it. Void uses runit, and services are managed with `sv`. [1]

```bash
sudo -u postgres psql -tAc 'SHOW unix_socket_directories'
```

Run this as the PostgreSQL admin or another role with write access to the tables. It inserts the three apps and uses `ON CONFLICT` so rerunning it updates their URLs and current versions instead of duplicating rows.

```sql
BEGIN;

INSERT INTO application (name)
VALUES ('hyprland'), ('librewolf'), ('xlibre')
ON CONFLICT (name) DO NOTHING;

INSERT INTO endpoint (app_id, url)
SELECT a.id, v.url
FROM (
    VALUES
        (
            'hyprland',
            'https://github.com/hyprwm/Hyprland/releases/download/v${version}/source-v${version}.tar.gz'
        ),
        (
            'librewolf',
            'https://librewolf.dev/api/packages/librewolf/generic/librewolf-source/154.0-2/librewolf-154.0-2.source.tar.gz'
        ),
        (
            'xlibre',
            'https://github.com/X11Libre/xserver/wiki'
        )
) AS v(name, url)
JOIN application a ON a.name = v.name
ON CONFLICT (app_id, url) DO NOTHING;

INSERT INTO app_version (app_id, version)
SELECT a.id, v.version
FROM (
    VALUES
        ('hyprland', '0.56.2'),
        ('librewolf', '154.0.2'),
        ('xlibre', '25.1.0')
) AS v(name, version)
JOIN application a ON a.name = v.name
ON CONFLICT (app_id)
DO UPDATE SET version = EXCLUDED.version, updated_at = now();

COMMIT;
```
